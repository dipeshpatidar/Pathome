# G10 Lead integration — genuine browser verification

This suite drives the production Vite build in Chromium against a random-port Spring Boot instance
and a UUID-owned schema in the approved disposable PostgreSQL database. It is launched by
`LeadHttpPostgresTest#genuineBrowserLeadJourneyUsesSpringPostgresAndProductionBuild`; it is not a
standalone stub-only suite.

```bash
PATHOME_VISIT_OPERATIONS_POSTGRES_TEST=true \
PATHOME_OE_TEST_ALLOW_DISPOSABLE=true \
PATHOME_LEAD_BROWSER_TEST=true \
PATHOME_OE_TEST_DB=pathome_oe_test_integration \
PATHOME_OE_TEST_DB_HOST=127.0.0.1 \
PATHOME_OE_TEST_DB_PORT=5432 \
SPRING_DATASOURCE_URL=jdbc:postgresql://127.0.0.1:5432/pathome_oe_test_integration \
SPRING_DATASOURCE_USERNAME=pathome \
SPRING_DATASOURCE_PASSWORD= \
mvn -q -f backend/pom.xml \
  -Dtest='LeadHttpPostgresTest#genuineBrowserLeadJourneyUsesSpringPostgresAndProductionBuild' test
```

Run `npm --prefix frontend-web run build` first. The test seeds only synthetic City/Team/public-listing
data inside its disposable schema and drops that schema in `@AfterAll`.

## Controlled asynchronous correction suite

`controlled-corrections.mjs` serves the same production build with a synthetic API transport. It is
separate from the genuine Spring/PostgreSQL journey and must never be reported as backend evidence.

```bash
npm --prefix frontend-web run build
node frontend-web/browser-verification/operations-leads/controlled-corrections.mjs
```

This pass holds duplicate lookup, Smart Search pagination, export-event acknowledgement and account
switch responses; verifies Clear/Cancel fencing; exercises explicit manual attachment, consent
withdrawal and read-only event recovery; and measures long filter values from 320px through 1440px.
Evidence is written to
`tools/oe-integration-env/evidence/p1-v0-fidelity-20261022/` by default.

Evidence is written to
`tools/oe-integration-env/evidence/g10-connected-20261022/`. It includes redacted method/path network
records, responsive screenshots, browser results and the child-process log. The final WhatsApp URL is
generated by the production component but intercepted locally; no WhatsApp network request or message
is made.

The pass covers authentication-bound Lead capture, detail editing, Smart Search empty/results states,
shortlist persistence, `PROPERTY_SHARING` consent, immutable share preparation, clipboard success and
failure fallback, manual handoff attempt, operator-reported send, persisted history reload, foreign-owner
concealment, supervisor read-only behavior, Staff Admin diagnostics access and a late-response account
switch. It does not substitute for physical iPhone/VoiceOver, real WhatsApp delivery, staging, or
independent acceptance.
